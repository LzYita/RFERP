# 部署与运维说明

面向实施与运维人员。开发与发布流程见 [CONTRIBUTING](../CONTRIBUTING.md)。

## 1. 运行环境

| 项 | 要求 |
|---|---|
| 操作系统 | Windows 10 / 11（64 位） |
| WebView2 运行时 | 必需。Windows 11 与带 Edge 的 Windows 10 已预装；缺失时程序会引导安装（详见下） |
| 数据库 | MySQL 8（默认，适合多人共用）或内嵌 SQLite（单机） |
| 权限 | 普通用户即可运行。**仅当本机 MySQL 服务没启动且启动它需要管理员权限时**，会弹一次 UAC |
| 安装目录 | **必须可写**：应用内更新要替换 exe，回退要改回 `.old` |

### WebView2 缺失时会发生什么

1. 启动时检测 → 缺失则询问是否自动安装；
2. 下载微软官方 Evergreen 引导程序 → **验签通过才执行** → 安装（会请求 UAC）；
3. 复检：装好即继续启动，**不需要重启**；
4. 失败可重试（最多 3 次），或改用手动下载页；用户放弃时，如果还留着上一版本，会询问是否回退。

## 2. 单实例

同一台机器上**只允许运行一个 RFERP 实例**（命名互斥体 `RFERP.SingleInstance`）。
第二个实例启动时会提示"RFERP 已在运行"后退出，不会抢数据库。

> 无头模式（`RFERP.exe -serve`，供开发与自动化验证）不参与单实例锁，
> 因此可以和窗口实例同时存在。**不要把它用于交付。**

## 3. 会话与登录

- 登录会话**只存在于进程内存**，不落盘。
- **重启程序 = 所有会话失效**（包括"记住登录"用户，需要重新登录一次）。
  这是有意的：没有服务器端会话存储，进程退出即视为登出。
- "记住登录"凭据用 Windows DPAPI 加密保存在本机数据目录的 `remember.bin`，
  只对**同一台机器、同一个 Windows 用户**有效。

## 4. 数据与备份位置

| 内容 | 位置 |
|---|---|
| 配置 | `%APPDATA%\RFERP\config.json`（也支持 exe 同目录、当前目录，按此顺序查找） |
| 数据目录 | 由配置决定；SQLite 库为 `<数据目录>\rferp.db` |
| 备份 | `<数据目录>\备份\`，下分 `manual\`（手动）、`auto\`（定期）、`safety\`（升级前自动快照） |
| 日志 | `<数据目录>\日志\` |
| 更新标记 / 回退副本 | 与 `RFERP.exe` 同目录：`RFERP.update-pending`、`RFERP.exe.old`、`RFERP.exe.failed` |
| 记住登录 | `<数据目录>\remember.bin` |

> 从 1.3.0 升级后，旧的平铺备份会被移入 `manual\ / auto\ / safety\`，
> 并写一份 `备份\layout-migration.log`。**降级回 1.3.0 时旧版看不到这些子目录**，
> 备份数据本身没有丢。

## 5. 更新与回退

- 更新通道：应用内检查 → 下载 zip → **Ed25519 清单验签 + SHA256 校验** → 替换 exe → 重启。
- 替换前会留下 `RFERP.exe.old`（上一版本），并在同目录写 `RFERP.update-pending`。
- **界面真正显示出来之后**才算这一版健康：清标记、删除 `.old`。
  收不到前端上报（例如前端资源损坏、界面白屏）就**不确认**，下次启动会问是否回退。
- 启动失败（数据库/服务起不来、界面出不来、缺 WebView2 且用户放弃）时，
  若有未确认标记和 `.old`，会询问是否回退；点"是"即把 `.old` 换回来，
  坏版本保留为 `RFERP.exe.failed` 供排查。
- **通过安装包或手工解压升级时不会产生 `.old`**，因此没有自动回退能力；
  只有应用内自更新才有。

> `.old` 是回退的唯一物质基础。不要手工删除它，杀毒软件若隔离它，
> 回退能力会静默失效（程序仍可正常使用，只是起不来时无法自动回退）。

## 6. 跨机访问：只走 VPN，不暴露公网

- 桌面版的内嵌 HTTP 服务**只绑定 `127.0.0.1`**，并带一次性启动凭据（Cookie），
  同机的其它进程直连会被拒绝。
- 需要多机共用时，**通过 VPN 组网访问，不要把端口映射到公网**。
- 远程形态下以下能力**有意禁用**（它们的前提是"操作者就是这台机器的主人"）：
  恢复备份、清空数据、更改数据目录、启动/停止 MySQL 服务。
- 不要为了"方便"关闭防火墙或改成 `0.0.0.0` 监听；那会同时绕过启动凭据的适用范围。

## 7. 升级前检查清单

- [ ] 安装目录可写（不是只读共享、不是无权限的 `Program Files` 子目录）
- [ ] 目标机器有 WebView2，或允许程序安装它（需要一次 UAC）
- [ ] 本机 MySQL 服务可启动（若用 MySQL）；服务名与端口和配置一致
- [ ] 已有一份可用备份（`备份\manual\` 或 `safety\`）
- [ ] 知道回退方式：应用内升级失败会主动询问；否则把 `RFERP.exe.old` 改名回 `RFERP.exe`
