> 记录留档。状态：方案定稿，尚未实施。

> - 更新方式：Go 原生自更新（Ed25519 签名清单 + SHA-256 + Authenticode 校验）

## 0. 架构总览

```
开发者/CI ──签名打包──> 阿里云 OSS Bucket ──HTTPS──> 客户端
                          │
                          ├─ Setup.exe                (首次安装, Inno)
                          ├─ releases.json            (更新清单, 签名)
                          └─ mes-app-1.2.3.zip        (更新包体, 签名)
                                     ↑
                            (可选) CDN + 自定义域名
```

- **安装**：Inno Setup 生成 `Setup.exe`，可自选路径；
- **托管**：阿里云 OSS（国内首选）；
- **更新**：Go 原生自更新，启动时读 `releases.json` 校验并替换。

## 2. 对象存储配置

### 2.1 Bucket 权限

Bucket 保持**私有**，用 **Bucket Policy** 只开放只读：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": ["*"],
      "Action": ["oss:GetObject"],
      "Resource": [
        "acs:oss:*:*:mes-updates/stable/*",
        "acs:oss:*:*:mes-updates/beta/*"
      ]
    }
  ]
}
```

**开启版本控制**（防误删/覆盖）。

### 2.2 RAM 上传账号（给 CI）

只允许写这两个前缀，不能删别的：

```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["oss:PutObject", "oss:GetObject", "oss:ListObjects"],
      "Resource": [
        "acs:oss:*:*:mes-updates/stable/*",
        "acs:oss:*:*:mes-updates/beta/*"
      ]
    }
  ]
}
```

### 2.3 目录结构

```
mes-updates/
├── stable/
│   ├── releases.json              # 客户端唯一读取（no-cache）
│   ├── mes-app-1.2.3.zip          # 更新包体（immutable）
│   └── Setup-1.2.3.exe            # 安装包（immutable）
└── beta/
    └── ...
```

### 2.4 缓存策略（对象级 Cache-Control）

| 对象 | Cache-Control |
|---|---|
| `*.zip` / `Setup*.exe` | `public, max-age=31536000, immutable` |
| `releases.json` | `no-cache` |

### 2.5 自定义域名（可选）

- 备案完成后：OSS 绑定域名 → 接 CDN → 回源 OSS；
- 不想备案：先用 OSS 默认域名 `mes-updates.oss-cn-hangzhou.aliyuncs.com`。

## 3. 应用改造（Go）

### 3.1 版本注入

```bat
go build -ldflags "-X main.version=1.2.3 -X main.commit=abc123" -o mes-app.exe cmd/desktop/main.go
```

程序内 `var version = "dev"` 暴露当前版本。

### 3.2 数据库凭据安全（替换现有明文）

- MySQL 建**专用最小权限账号**（只对该库 CRUD），不用 root；
- 密码用 **Windows DPAPI** 加密存盘，运行时解密；
- `config.json` 只放非敏感项（地址、端口、库名）。

> 现状问题：`install.ps1` 曾把 MySQL root 明文密码写入 `config.json`，需一并整改。

### 3.3 自更新模块（核心）

**启动流程：**

1. `GET https://.../stable/releases.json`；
2. 用**内嵌公钥验 Ed25519 签名**，失败 → 放弃；
3. 比较版本：`新 > 当前` 且 `新 >= minVersion` 且**拒绝降级**；
4. 检查安装目录**可写**（不可写则提示，不静默失败）；
5. 下载 `.zip` 到临时目录，校验 **SHA-256**；
6. 解压出 `mes-app.exe`，校验其 **Authenticode 签名主体**；
7. **重命名**当前 exe 为 `mes-app.old` → 写入新 exe；
8. 拉起新进程并退出；
9. 下次启动删除 `mes-app.old`（失败可回滚）。

> 建议**异步执行**，不阻塞界面；加"跳过此版本"开关。

### 3.4 清单格式（发布脚本生成）

```json
{
  "version": "1.2.3",
  "channel": "stable",
  "minVersion": "1.0.0",
  "url": "https://.../stable/mes-app-1.2.3.zip",
  "size": 52428800,
  "sha256": "……",
  "notes": "修复……",
  "publishedAt": "2026-09-19T10:00:00Z",
  "sig": "base64(Ed25519 对不含 sig 的规范 JSON 的签名)"
}
```

## 4. 安装包（Inno Setup）

关键指令：

```ini
[Setup]
AppName=制造仓储管理系统
AppId={{你的固定GUID}}
AppVersion=1.2.3
; 默认装到用户可写目录 → 更新可静默、无需 UAC
DefaultDirName={localappdata}\Programs\MES
DisableDirPage=no          ; 允许用户自选路径
PrivilegesRequired=lowest  ; 程序本体不提权
ArchitecturesAllowed=x64compatible
SignTool=mysign
SignedUninstaller=yes

[Files]
Source: "dist\mes-app.exe"; DestDir: "{app}"

[Registry]
Root: HKCU; Subkey: "Software\MES"; ValueName: "InstallDir"; ValueData: "{app}"
```

- **MySQL 服务**需要管理员权限，用单独的 `[Run]` + `runas` 提权**只装一次**（或做成独立前置安装器）；
- 若用户把路径改到 `Program Files`，需在界面上**提示"将无法无感自动更新"**（更新要 UAC）。

### 关键冲突说明：自选路径 vs 静默自动更新

自动更新需往程序目录写新 exe。若装到 `C:\Program Files\...`，程序以普通权限运行则无写权限，更新会失败或每次弹 UAC。

| 方案 | 做法 | 评价 |
|---|---|---|
| ① 限制可选路径为用户可写区（推荐） | 默认/推荐 `%LocalAppData%\Programs\MES` 或 `D:\MES`；更新静默、无 UAC | 体验最好，安全也好 |
| ② 装 Program Files + 更新提权 | 更新时 `ShellExecute runas` 弹 UAC | 每次更新弹窗，体验差 |
| ③ 装 Program Files + 首次安装授写权限 | 安装时 `icacls` 给当前用户加目录 ACL | 削弱防篡改，不推荐 |

> 程序用 `os.Executable()` 即可知自身安装位置，**自选路径本身不影响更新**，真正影响的只是**写权限**。

## 5. 发布流程（上传）

### 5.1 本地脚本

```powershell
# 1) 构建 + 签名 exe
go build -ldflags "-X main.version=1.2.3" -o dist\mes-app.exe cmd\desktop\main.go
signtool sign /fd SHA256 /tr http://timestamp.digicert.com /td SHA256 /a dist\mes-app.exe

# 2) 打更新包 + 生成签名清单（脚本计算 sha256 并用 Ed25519 私钥签名）
Compress-Archive dist\mes-app.exe dist\mes-app-1.2.3.zip
# 生成 releases.json ...

# 3) 先传包体（immutable）
ossutil cp dist\mes-app-1.2.3.zip oss://mes-updates/stable/ `
  --meta "Cache-Control:public, max-age=31536000, immutable"

# 4) 最后传清单（no-cache）
ossutil cp dist\releases.json oss://mes-updates/stable/ `
  --meta "Cache-Control:no-cache"

# 5) 若用 CDN：只刷清单
# 阿里云 CDN 刷新 URL: /stable/releases.json
```

### 5.2 CI（推荐）

tag 触发 → 构建 → 签名 → 打包 → 生成签名清单 → `ossutil cp` → 刷 CDN 清单缓存。AK/SK 与 Ed25519 私钥放 **CI secrets**。

### 5.3 原子发布顺序（必须遵守）

1. 传所有包体；
2. **最后**传 `releases.json`。

→ 客户端永远不会读到指向缺失文件的清单。

## 6. 客户端更新时序

```
启动 → 后台 GET releases.json → 验签
   ├─ 失败/无新版 → 正常启动
   └─ 有新版 → 下载 zip → 验 sha256 → 验 exe 签名
                 → 重命名替换 → 重启 → 启动时清理旧文件
```

## 7. 安全清单

| 风险 | 措施 |
|---|---|
| 服务器/桶被投毒 | 清单 Ed25519 验签 + 包 SHA-256 + exe Authenticode 主体校验，**三重校验** |
| 中间人 | 强制 HTTPS，客户端**禁止跳过证书校验** |
| 密钥泄露 | 主账号 AK 禁用；CI 用最小权限 RAM；私钥只在 secrets |
| 数据库凭据 | 弃用 root、专用账号、DPAPI 加密 |
| 降级攻击 | 客户端拒绝低版本、校验 `minVersion` |
| 误覆盖 | Bucket 版本控制 + 包名含版本（immutable） |
| 提权滥用 | 程序本体 `lowest`，仅 MySQL 前置提权 |
| 本地篡改 | 安装目录 ACL 收紧；exe 启动时自校验签名 |

## 9. 测试与验收

1. **全新安装**：新机跑 `Setup.exe`，自选路径 → 建库 → 启动正常；
2. **更新**：发 1.2.3，旧版启动后自动升级并重启；
3. **安全**：篡改清单/包 → 客户端**拒绝更新**；
4. **回滚**：重新上传旧版清单 → 客户端回退（在允许策略内）；
5. **弱网/断网**：更新失败不影响正常使用。

---

## 10. 回滚

- 把**上一版 `releases.json`** 重新上传覆盖（清单 `no-cache`，很快生效）；
- **不要删旧包**（immutable 保证可拉取）；
- 紧急时也可下架整个 channel 清单。

## 附：术语与备选

- **对象存储**：云上的静态文件仓库 + 自带 HTTPS 下载地址，无需自管服务器。国内可选阿里云 OSS、腾讯云 COS、华为云 OBS；海外 AWS S3、Cloudflare R2；自建 MinIO。
- **ICP 备案**：大陆用自有域名对外提供服务必须备案；用 OSS 默认域名或香港/海外节点可免备案。
- **Velopack / Squirrel**：无官方 Go SDK，故本方案客户端自实现；`vpk` 仅可选用于打包。
- **备选托管**：GitHub Releases（免费但国内慢）、自建 Nginx（可控但需自管运维与安全）。
